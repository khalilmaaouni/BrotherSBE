Each line ends with what enforces it. [checked: tool] means a script decides it and CI can block on it. [human] means nothing computes it, and the line is a stated discipline, not a control. Reading a rule without knowing which it is recreates the overclaim these laws were rewritten to remove.

- Four HARD gates (tools/sbe_gate.py, --strict blocks in CI, never waived by impatience): L7 numbers (real snapshot id, a second derivation that differs and still computes, a claimed re-run, zero drift between real numbers), L8 migration (both legs against a restore, rehearsal id, whole matching row counts; no counts is NO-DATA), L9 approval (only a host-verified signed Approved-by trailer naming somebody other than author and committer PASSes; self-approval FAILs; an unverifiable signature or a Reviewed-in id is NO-DATA), L10 ran (each recorded check names what ran, exit 0, positive duration). L11 lints is the fifth thing CI runs under --strict, so L7 to L11 are refused, not waived. [checked: sbe_gate.py, sbe_score.py]
- Receipts have three states: no receipt is NO-DATA, a receipt recording zero items is NO-DATA and says so, a receipt that cannot be parsed FAILs. Emptiness is a VALUE test against one shared, scoped list (sbe_checks.VACUOUS_VALUES); thresholds count DISTINCT items; a future timestamp FAILs. The declaration is enforced (sbe_checks.py refuses a check whose empty state is PASS or that ships no hollowable worked example) and the runtime is swept (evals/test_no_data_class.py imports every .py under tools/ and hollows every declared example, requiring never PASS); that is a mechanical sweep, not a proof over all inputs. A crashing check is a FAIL carrying the exception, never a missing line. [checked: sbe_checks.py, evals/test_no_data_class.py]
- Severity is declared at write time in each check's constructor: gate means a FAIL blocks a --strict run, soft means a FAIL is graded and blocks only under the opt-in --strict-soft. It prints on every verdict line, a check declaring neither is refused registration, and it changes only the exit code, never what a check examines. [checked: sbe_checks.py; the shipped CI passes --strict-soft, so graded FAILs still block there]
