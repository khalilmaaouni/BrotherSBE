# Loop 2: Decision Packages and Lineage, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `src/brothersbe/decisions.py`: a decision package written automatically at the four moments the spec names (a gate FAIL, a WAIVED check, a tier raised or disposed, a forced task close), browsable and regenerable through `sbe explain`, plus `sbe lineage <artifact>` walking the chain for any artifact oldest to newest with an evidence pointer on every hop.

**Source spec:** `docs/specs/2026-07-30-team-docs-collab-book-design.md`, "Feature 2: decision packages, `sbe explain`, `sbe lineage`", plus that spec's global constraints and program table (L2 is one session, and lineage ships WITH Feature 2, not later).

**Architecture:** `decisions.py` is a READER and a WRITER of files, never a second gate runner. It follows the precedent `src/brothersbe/status.py` set and states in its own docstring: nothing in it recomputes a verdict over source code, and nothing in it starts a gate. A package quotes verdict lines produced by the real tools at the moment they were printed, records the deciding code by importing the shipped check registry and reading its source with `inspect`, and binds itself to the head commit it was written against. Packages are versioned files under the dossier, like every other artifact this project ships.

**Tech Stack:** Python 3.9 standard library only. Mermaid for the check-logic flowchart, written as text into Markdown, rendered by whatever already renders the repository's other Mermaid.

## Global Constraints (verbatim from the spec, INVARIANTS.md, SKILL.md, and this repo's laws)

- Python 3.9+, standard library only. No third-party package, no network call at run time, no `match` statement, no `X | Y` annotation.
- Zero em dashes and zero en dashes in every file this loop touches, code comments and prose alike.
- **Absent evidence is NO-DATA and never PASS (I1).** A package this loop cannot fill renders NO-DATA naming what would fill it. A broken claim is FAIL. A waived control is WAIVED and never PASS (I7). This loop introduces no new verdict word; it REPORTS the four that exist.
- **No helper in this loop may return a bare two-value tuple.** `evals/test_no_data_class.py` refuses any function returning a `(verdict, evidence)`-shaped pair outside a check registry, and it reads lists, `IfExp` returns and forwarded calls as pairs too. Every helper here returns a dict with named keys, or three values, or a single value. Where a caller wants two things, it reads two keys off one dict, or calls two accessors. State this in the module docstring so the next writer does not reintroduce it.
- No task in this loop may construct a git merge, rebase, push or deploy. `decisions.py` never writes to a remote and never mutates git state; it reads `git log`, `git rev-parse` and `git diff` only.
- Every new behavior is held by a test in `tools/`, named `tools/test_sbe_decisions.py`, following the naming already there.
- Every new fixture calibrated: break the control, watch red, restore. Every eval case added to `evals/run_evals.py` plants its defect and asserts the check catches it.
- No silent except. Every `except` names its exception class and either raises, returns a NO-DATA-carrying value, or carries a `# sbe: allow-silent <reason>` marker with a real reason (L11 READS the reason; a bare marker waives nothing).
- Numbers printed in docs must be recomputed from a live run, never typed from memory. `CHECKSUMS.sha256` is regenerated by the orchestrator after staging, never by a task.
- Maturity language: INTERNAL-EVAL everywhere.

## Assumptions this plan writes down, because the spec leaves them open

1. **Where the verdict text comes from.** Evidence receipts persist digests only and never raw output (`src/brothersbe/evidence.py`, `outputPolicy`), so a package cannot quote a verdict out of a receipt. This plan captures the verdict lines at the CLI boundary with a tee (echo every line to stdout as it arrives, keep a copy), and quotes ONLY lines matching the shipped verdict-line grammar. Every other line is counted, not copied, and the package prints that count, so the receipt's secrets policy is not quietly widened by a new artifact that is also shared.
2. **Where a package lives when there is no dossier.** The spec says `design/<project>/decisions/NNN-<slug>/`. When the checked directory carries no `00-intake.json`, there is no project to name, so packages go to `.sbe/decisions/NNN-<slug>/` at the repository root and the package says in its own header which of the two locations it is in and why. Nothing invents a project name.
3. **Notes.** The spec's lineage includes "notes on it", and `notes.py` ships in Loop 4. The notes hop renders NO-DATA naming `.sbe/notes/<artifact-key>/` as the store that would fill it. It is a named absence, never a dropped hop and never silence.

```python
class DecisionUnwritable(Exception):
    """The package could not be written, so nothing was recorded. Raised
    rather than returning a path that does not exist: a decision nobody can
    open is not a decision that was taken."""


def next_id(decisions_dir):
    """The next NNN, allocated by READING the directory. An unreadable
    directory raises rather than restarting at 001: restarting would write a
    second 001 over somebody's first one."""
    if not os.path.isdir(decisions_dir):
        return "001"
    try:
        entries = os.listdir(decisions_dir)
    except OSError as exc:
        raise DecisionUnwritable("%s cannot be listed (%s); refusing to allocate an id "
                                 "that may already be taken" % (decisions_dir, exc))
    highest = 0
    for name in entries:
        head = name[:3]
        if head.isdigit():
            highest = max(highest, int(head))
    return "%03d" % (highest + 1)
```

### Task 5: `sbe explain`: browse a package, regenerate one, and never overwrite another commit's

**Files:**
- Modify: `src/brothersbe/decisions.py` (add `explain`, `main`)
- Modify: `src/brothersbe/cli.py` (add `("explain", ...)` to the `COMMANDS` table and its parser branch)
- Modify: `tools/test_sbe_decisions.py` (append class `TestExplain`)

**Interfaces:**
- Produces: `bin/sbe explain <gate|check|decision-id>`. A decision id prints that package. A gate or check name with a package prints the newest one bound to the current head. A gate or check name with no package REGENERATES one from the shipped registry (deciding code, flowchart, checklist) and marks the verdict section NO-DATA, because no run has been made.

Constraints restated where they bite: no helper in this plan returns a two-value tuple, and every reference snippet above obeys that, because a plan whose example code breaks its own rule teaches every task that copies it the same defect. No task constructs a merge, rebase, push or deploy. Every task names one literal done-check command.

Left open on purpose, and named rather than guessed: the spec does not say what a decision package should do when the SAME check fails twice against the SAME commit. This plan allocates a new `NNN` either way, because packages are append-only, and flags the question for the founder at the Task 5 review rather than inventing a dedup rule that would quietly hide a second failure.
